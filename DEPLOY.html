Деплой Mirai Lounge

Пуш в main — и сайт обновился сам. Ниже: разовая настройка сервера, первый деплой и повседневный цикл. Глубокий референс по ОС и сети — в SERVER_SETUP.

Стек
Slim 4 · Postgres 16 · Vite · Docker
Хост
Ubuntu, за NAT, вход по паролю
Деплой
self-hosted runner + ручной фолбэк
Данные
Postgres в томе — --delete не трогает

Два пути деплоя

Основной — автоматический через GitHub Actions. Ручной — на случай, когда GitHub недоступен.

Основной

GitHub Actions

Push в main → CI на GitHub (тесты, сборка) → CD на self-hosted runner прямо на сервере: локальный rsync + docker compose + миграции. Ни SSH, ни секретов, ни проброса — runner сам ходит исходящим HTTPS.

Фолбэк

scripts/deploy.sh

Прямой rsync + ssh с рабочей машины одной командой. Настройка — в scripts/README. Пригодится, когда GitHub лежит или нужно выкатить срочно мимо пайплайна.

1× Разовая настройка

Делается один раз на свежем сервере. Четыре шага сверху вниз.

1 · Сервер (ОС, сеть, доступ)

Если сервер «сырой» — netplan, статический адрес, проброс 80/443, SSH на нестандартном порту, ufw, fail2ban: см. SERVER_SETUP, Часть I. Нужен пользователь deploy в группе sudo.

2 · Подготовка под приложение — одной командой

рабочая машина → сервер
# ставит Docker, создаёт каталог и .env со сгенерированными ключами
scp -P <ssh-порт> scripts/server-bootstrap.sh deploy@<сервер>:/tmp/
ssh -t -p <ssh-порт> deploy@<сервер> "sudo bash /tmp/server-bootstrap.sh"  # -t: sudo нужен TTY
i

server-bootstrap.sh генерирует случайные MIRAI_TABLE_SIGNING_KEY и пароль Postgres. Без ключа prod не поднимется (fail-closed) — это защита, не баг.

3 · TLS-сертификаты (Reg.ru, без Let's Encrypt)

Скопировать с рабочей машины (пример — macOS, серты на рабочем столе ~/Desktop). Каталог создал bootstrap, владелец deploy — sudo не нужен:

рабочая машина → сервер
scp -P <ssh-порт> ~/Desktop/fullchain.pem ~/Desktop/privkey.pem \
    deploy@<сервер>:/var/www/mirailounge/docker/ssl/mirailounge.ru/
ssh -p <ssh-порт> deploy@<сервер> \
    "chmod 600 /var/www/mirailounge/docker/ssl/mirailounge.ru/privkey.pem"
i

fullchain.pem = сертификат + цепочка CA. Если от Reg.ru отдельные файлы — собрать перед копированием: cat certificate.crt certificate_ca.crt > ~/Desktop/fullchain.pem. Серты живут только на сервере — rsync их не несёт.

Проверить, что ключ подходит к сертификату (хеши должны совпасть):

проверка пары
ssh -p <ssh-порт> deploy@<сервер> '
  d=/var/www/mirailounge/docker/ssl/mirailounge.ru
  echo cert: $(openssl x509 -noout -modulus -in $d/fullchain.pem | openssl md5)
  echo key:  $(openssl rsa  -noout -modulus -in $d/privkey.pem  | openssl md5)'

4 · Self-hosted runner (для авто-деплоя)

Токен — в Settings → Actions → Runners → New self-hosted runner. На сервере под deploy:

deploy@сервер · ~/actions-runner
# скачать актуальный runner с GitHub, распаковать, затем:
./config.sh --url https://github.com/isinuytin27/mirai_lounge_menu \
  --token <токен> --labels self-hosted,mirai-prod --unattended
sudo ./svc.sh install deploy && sudo ./svc.sh start   # автозапуск
i

После этого runner горит Idle в Settings → Actions → Runners. Секреты DEPLOY_* больше не нужны — можно удалить.

2× Первый деплой

Мёрдж в main запускает пайплайн. Затем — разовое наполнение справочников.

рабочая машина
git checkout main && git merge rebuild/foundation && git push

Когда стек поднялся — разово наполнить справочники на сервере:

на сервере · /var/www/mirailounge/docker
docker compose exec -T php php bin/import-recommender   # граф гастропар
docker compose exec -T php php bin/import-vitrina       # витрина кальянов
# если есть старые данные — положить data/*.json и ОДИН раз:
docker compose exec -T php php bin/import-json
# первый администратор:
docker compose exec php php bin/create-admin <логин> <пароль> owner
!

Миграции применяет сам пайплайн на каждый деплой. Импорт данных в пайплайн не входит — он разовый: повтор import-json затрёт правки из админки старым снимком JSON.

∞ Обычный деплой

Дальше — просто пуш. Или вручную, если нужно.

каждый релиз
git push                         # в main → GitHub Actions выложит сам

# или вручную (фолбэк, с рабочей машины):
./scripts/deploy.sh              # собрать → залить → поднять → миграции
./scripts/deploy.sh --dry-run    # посмотреть, что зальётся, ничего не меняя

Проверка

smoke
curl -I https://mirailounge.ru/            # 200 / 301
curl -s https://mirailounge.ru/_health     # {"status":"ok"}

Руками пройти по экранам:

/ витрина + меню /vitrina карусель кальянов /booking/map 3D-зал /orders панель заказов /admin вход

Эксплуатация

на сервере · /var/www/mirailounge/docker
docker compose ps
docker compose logs -f php
docker compose restart php nginx
docker compose exec -T php php vendor/bin/phinx rollback -c phinx.php   # откат миграции
docker exec -it mirai-postgres psql -U mirailounge -d mirailounge       # psql

# бэкап БД (по cron)
docker exec mirai-postgres pg_dumpall -U mirailounge | gzip > ~/backups/pg-$(date +%F).sql.gz

СимптомПричина / лечение

Страницы без стилейНет public/dist/ — сборка Vite / артефакт не доехали
Витрина пустаяНе запускали bin/import-vitrina

i

Деплой не перезаписывает: том Postgres (data/pg), .env, серты (docker/ssl/), загрузки из админок (*/uploads/), локальный scripts/deploy.env. png-ассеты меню/карты/витрины возвращаются в выкладку явными --include. Список — scripts/deploy-excludes.txt.
